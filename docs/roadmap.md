# Roadmap

## Phase 0 — Foundation

- repository structure
- architecture documentation
- Claude Code operating contract
- privacy boundaries
- knowledge model
- Librarian specification

## Phase 1 — Local vault

- establish separate Obsidian vault
- define inbox and core folders
- establish lightweight frontmatter
- establish backup/versioning
- test Markdown portability

## Phase 2 — Librarian v0

- deterministic intake
- source fingerprinting
- metadata extraction
- basic routing
- dry-run mode
- audit log

## Phase 3 — Local AI

- Ollama integration
- configurable model adapter
- classification prompts
- confidence scoring
- local-only processing path

## Phase 4 — Automation

- n8n intake workflows
- scheduled processing
- review queue
- notifications where useful
- error/retry handling

## Phase 5 — Retrieval

- lexical search
- semantic search as a derived index
- related-note discovery
- natural-language retrieval

## Phase 6 — Dashboard

Build only after the underlying knowledge flow works.

Potential views:

- inbox
- recently changed knowledge
- projects
- areas
- questions
- decisions
- review queue
- agent activity
- search

## Phase 7 — Specialized agents

Examples could include research, writing, planning, review, and personal knowledge synthesis. Each must have a narrow scope and documented permissions.

## Phase 8 — Advanced integrations

Potential future integrations include Kindle Scribe ingestion, calendar/tasks, email, browser research, and other sources. Add integrations only when they reduce friction without compromising privacy or maintainability.
